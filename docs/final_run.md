# Финальный час: контрольный набор (PROD)

Организаторы выдают 10 контрольных чатов через тот же API за час до стоп-кода. Нужно оценить их и сделать
push файла `results/prod/results.json` в открытый репозиторий. Без push не засчитывается.

Запускать на ноутбуке, где установлены Ollama и `gemma4:e4b` (резерв на случай отказа облака).

## Заранее (до 22-го часа)

1. `git checkout main && git pull`, затем `pytest`: все тесты зелёные.
2. `.env` на этом ноутбуке:
   ```ini
   CQA_ORG_API_URL=...ссылка организаторов...
   CQA_TEAM_NAME=Utopia
   GROQ_API_KEY=...ключ ИЗ ОТДЕЛЬНОГО аккаунта Groq, который до финала не использовали...
   CQA_MODEL=groq/openai/gpt-oss-120b
   CQA_FALLBACK_MODELS=ollama_chat/gemma4:e4b
   CQA_RPM=0
   CQA_RESAMPLE=1
   ```
   Лимит Groq общий на аккаунт (не на ключ): 200 000 токенов в сутки, ~7 000 на диалог.
   Новый ключ в том же аккаунте лимит не обновляет. `CQA_RESAMPLE=1`: повторный опрос съел бы бюджет.
   Если есть платный ключ - поставить его моделью, а Groq и Gemma резервом.
3. Проверить, что Ollama работает: `ollama list` показывает `gemma4:e4b`.
4. Репетиция на одном диалоге (≈7 000 токенов из 200 000):
   `python -m eval.make_results --group DEV --ids p1-ru-001` → итог 92.31.
5. Проверить, что `git push` с этого ноутбука проходит (доступ к репозиторию).
6. Ноутбук на зарядке, сон отключён.

## В финальный час

```bash
python -m eval.make_results --group PROD --workers 2   # только Groq без платной модели: --workers 1
```
- **Первая строка вывода - чек-лист.** «Чек-лист: версия N, совпадает с config/checklist.default.json» - всё в
  порядке. «⚠ Действующий чек-лист отличается…» - если это правки из демо (например, меняли вес), сразу Ctrl+C и:
  `python -m eval.make_results --group PROD --workers 2 --reset-checklist`. Если критерий заменили организаторы -
  предупреждение ожидаемо, флаг не добавлять.
- Скачивает набор, оценивает, пишет `results/prod/results.json` и проверяет формат.
- `--workers 1`: у бесплатного Groq 8 000 токенов в минуту, это ~1 диалог в минуту, 10 чатов ≈ 12 минут.
- Если организаторы назовут набор иначе (например `group_id=CONTROL`):
  `python -m eval.make_results --group PROD --api-group CONTROL --workers 1`.
- Если часть диалогов упала - запустить ту же команду ещё раз: доделает только упавшие.

Затем:
```bash
python -m eval.make_results --group PROD --check     # «формат верный, записей 10»
git add results/prod/results.json
git commit -m "results PROD"
git push
```
И открыть файл на GitHub в браузере: убедиться, что он там.

## Если на контроле заменят критерий

Организаторы могут заменить один критерий и попросить переоценить уже обработанные диалоги.

1. Чек-лист в интерфейсе (`/ui` → «Чек-лист»): изменить критерий на месте или удалить старый и добавить новый.
   В «Инструкция для ИИ, секция и код» выбрать **код заменённого критерия** (в файле сдачи только 8 кодов).
2. «Сохранить чек-лист». Если появилось ⚠ (например, «формат сдачи не допускает N/A для empathy») - исправить
   (снять «N/A разрешён», поправить шкалу) и сохранить снова. Без ⚠ файл пройдёт проверку.
3. Та же команда: `python -m eval.make_results --group PROD --workers 1`.
   Она переоценит только новый/изменённый критерий, остальные ответы возьмёт из прошлой оценки.
   Строка «⚠ Действующий чек-лист отличается…» здесь ожидаема - `--reset-checklist` НЕ добавлять, иначе замена
   отменится.
4. `--check` → `git add` → `commit` → `push`.

Репетиция (3 диалога DEV): переоценка заняла 11 с и $0.0013; без шага 2 файл не прошёл бы проверку.

## Время (репетиция на 10 чатах DEV, Claude Haiku 5.5 с повторным опросом)

Скачивание из API + оценка + запись файла - 2 мин 47 с, проверка - <1 с, commit+push - 3 с, стоимость $0.05.
При отказе основной модели переход на Groq произошёл сразу (проверено).
С платной моделью можно `--workers 2`; только Groq - `--workers 1`.

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Groq отвечает «rate limit ... per minute» | ничего: программа сама ждёт и повторяет |
| Groq исчерпан или недоступен | программа сама переходит на локальную Gemma (~5 мин на диалог) |
| До стоп-кода 15 минут, а часть ещё не готова | сразу push того, что есть: недоделанные записаны как `status: "error"`, файл валиден. Потом продолжить и сделать push ещё раз |
| API организаторов не отвечает | повторить с `--refetch`; написать организаторам |
| `--check` показывает ошибки формата | прислать вывод в чат команды; не править JSON руками |

Время: скачивание ~1 мин, оценка ~12 мин (Groq) или до ~50 мин (только Gemma), проверка и push ~2 мин.
